# Mastodon 投票功能实现分析

## 一、整体架构概览

Mastodon 的投票功能采用典型的分层架构：**业务分发层**（Ruby Sidekiq）负责决策"谁需要收到更新"，**传输层**（Node.js Streaming API）负责"如何将消息推送到前端"，两层通过 Redis Pub/Sub 解耦。

```
┌─────────────────────────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────────────────────────┤
│  ┌──────────────┐     ┌──────────────┐     ┌─────────────────────────────────────┐ │
│  │ Poll.tsx     │────▶│  Redux Store │◀────│  stream.js (WebSocket Client)       │ │
```

## 二、传输层与业务分发层的职责边界

### 2.1 清晰的分层职责

| 层级 | 组件 | 核心职责 | 是否关心投票业务逻辑 |
|------|------|----------|----------------------|
| **业务分发层** | `VoteService`, `DistributePollUpdateWorker`, `PushUpdateWorker` | **决定**"谁"需要收到更新、**何时**发送、**是否**应该发送 | ✅ 关心 `hide_totals`、延迟策略、收件人筛选 |
| **传输层** | `streaming/index.js` (Node.js) | **传输**消息，从 Redis 订阅 → WebSocket 推送 | ❌ 不关心投票逻辑，只处理通用的 `update`/`status.update` 事件 |

## 四、hide_totals 的精确语义分析

### 4.1 核心问题澄清

**用户可能存在的误解**:
```
❌ hide_totals = true 意味着"匿名投票"，所以：
   - 没有人知道我投了谁
   - 投票者身份被隐藏
```

**实际情况**:
```
✅ hide_totals = true 实际上隐藏的是：
   - 投票过程中的**实时票数变化** (cached_tallies, voters_count)
   
⚠️ 投票者身份**从来没有**通过 API 暴露给普通用户：
   - 无论 hide_totals 是 true 还是 false
   - 普通用户无法通过 API 查询"谁投了票"
```

### 4.4 三层延迟保护策略

即使是非匿名投票 (`hide_totals = false`)，Mastodon 也有多层保护防止时间推断：

| 保护层级 | 实现方式 | 效果 |
|----------|----------|------|
| **Layer 1: 3 分钟延迟广播** | `perform_in(3.minutes)` | 投票后不会立即推送，时间信息模糊 |
| **Layer 2: 批量合并** | `DistributePollUpdateWorker` 只收集一次 | 3 分钟内的所有投票合并成一次推送 |
| **Layer 3: 无逐票通知** | 没有"某人投了票"的通知类型 | 无法通过通知追踪 |

### 4.5 hide_totals 语义总结表

| 维度 | hide_totals = true | hide_totals = false |
|------|---------------------|----------------------|
| **过程票数可见性** | ❌ 投票进行中不可见 | ✅ 延迟 3 分钟后可见 |
| **最终票数可见性** | ✅ 过期后可见 | ✅ 过期后可见 |
| **当前用户自己的投票** | ✅ 可见 (`voted`, `own_votes`) | ✅ 可见 |
| **其他用户的投票身份** | ❌ API 从不暴露 | ❌ API 从不暴露 |
| **WebSocket 推送** | ❌ 投票进行中无推送 | ✅ 延迟 3 分钟后推送 |
| **过期通知** | ✅ 有 (from_account = 创建者) | ✅ 有 (from_account = 创建者) |
| **管理员可见性** | ✅ 数据库中有记录 | ✅ 数据库中有记录 |

### 4.6 常见误解澄清

| 误解 | 事实 |
|------|------|
| "hide_totals 隐藏投票者身份" | ❌ 投票者身份**从不**通过 API 暴露给普通用户，无论 hide_totals 值如何 |
| "匿名投票就是完全匿名" | ⚠️ 服务器数据库中仍有 `PollVote.account_id` 记录，管理员可查 |
| "非匿名投票可以看到谁投了票" | ❌ 非匿名投票只能看到**票数**，看不到投票人身份 |
| "hide_totals = true 时服务器不记录投票" | ❌ 服务器仍创建 `PollVote` 记录，用于去重和过期通知 |
| "非匿名投票会实时推送" | ❌ 非匿名投票也有 **3 分钟延迟**，防止时间推断 |

## 六、投票业务逻辑层

### 6.1 VoteService 核心流程

**文件位置**: `app/services/vote_service.rb`

```ruby
def call(account, poll, choices)
  return if choices.empty?

  authorize_with account, poll, :vote?

  @account = account
  @poll    = poll
  @choices = choices
  @votes   = []

  # 分布式锁防止重复投票
  with_redis_lock("vote:#{@poll.id}:#{@account.id}") do
    already_voted = @poll.votes.exists?(account: @account)

    ApplicationRecord.transaction do
      @choices.each do |choice|
        @votes << @poll.votes.create!(account: @account, choice: Integer(choice))
      end
    end
  end

  increment_voters_count! unless already_voted

  ActivityTracker.increment('activity:interactions')

  # 根据投票是否为本地实例，执行不同的分发策略
  if @poll.account.local?
    distribute_poll!   # 本地投票：检查 hide_totals，决定是否广播
  else
    deliver_votes!      # 远程投票：投递到源实例
    queue_final_poll_check!
  end
```

## 七、截止时间与过期机制

### 7.1 过期定时任务

**文件位置**: `app/workers/poll_expiration_notify_worker.rb`

```ruby
def perform(poll_id)
  @poll = Poll.find(poll_id)

  return if missing_expiration?
  requeue! && return if not_due_yet?

  notify_remote_voters_and_owner! if @poll.local?
  notify_local_voters!
end

def notify_remote_voters_and_owner!
  # 广播最终结果到 ActivityPub 网络
  ActivityPub::DistributePollUpdateWorker.perform_async(@poll.status.id)
  # 通知投票创建者
  LocalNotificationWorker.perform_async(@poll.account_id, @poll.id, 'Poll', 'poll')
end

def notify_local_voters!
  # 批量通知所有参与投票的本地用户
  @poll.voters.merge(Account.local).select(:id).find_in_batches do |accounts|
    LocalNotificationWorker.push_bulk(accounts) do |account|
      [account.id, @poll.id, 'Poll', 'poll']
    end
  end
end
```

## 九、关键设计决策总结

### 9.1 并发控制

| 问题 | 解决方案 | 代码位置 |
|------|----------|----------|
| 同一用户重复投票 | Redis 分布式锁 `vote:{poll_id}:{account_id}` | `vote_service.rb:21`, `activity/create.rb:360` |
| 高并发计数不准 | 乐观锁 + 自动重试 `lock_version` | `poll_vote.rb:37-39` |
| 远程投票去重 | `PollVote.uri` (ActivityPub URI) | `activity/create.rb:362` |

### 9.2 隐私保护层级

| 层级 | 保护对象 | 实现方式 |
|------|----------|----------|
| **Layer 1** | 过程票数实时变化 | `hide_totals = true` 时 `show_totals_now? = false` |
| **Layer 2** | 时间推断 | 非匿名投票也延迟 3 分钟广播 |
| **Layer 3** | 投票者身份 | API 层面从不暴露 `PollVote.account_id` 给普通用户 |
| **Layer 4** | 批量合并 | 3 分钟内的所有投票合并成一次推送 |

### 9.3 本地与远程投票的一致性

| 行为点 | 本地投票 | 远程投票 |

## 十一、核心设计亮点

### 1. **传输层与业务层解耦**
- 业务层 (Ruby) 只关心"谁需要收到更新、何时发送"
- 传输层 (Node.js) 只关心"如何高效推送"
- 通过 Redis Pub/Sub 解耦，两层可独立扩展

### 2. **hide_totals 的精确语义设计**
- 保护的是**过程票数**，不是投票人身份
- 投票人身份**从来没有**通过 API 暴露给普通用户
- 即使非匿名投票，也有 3 分钟延迟防止时间推断

### 3. **本地与远程投票的一致性**
- 远程投票通过 ActivityPub 接收后，走完全相同的业务逻辑
- 相同的 Redis 锁、相同的 hide_totals 判断、相同的延迟广播
- 确保联邦宇宙中的投票行为一致

### 4. **三层延迟保护**
- Layer 1: `hide_totals = true` 完全隐藏过程票数
- Layer 2: 非匿名投票也延迟 3 分钟广播
- Layer 3: 3 分钟内的所有投票合并成一次推送

### 5. **通知的 from_account 设计**
- `type: :poll` 通知的 `from_account` 是投票**创建者**，不是投票人
- 这是有意设计：用户收到的是"你参与的投票已结束"，不是"某某人投了票"
